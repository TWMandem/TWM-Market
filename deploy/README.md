# Сервер TWM Market на VPS

Установка занимает 5–10 минут и делается одной командой. Нужен VPS
**в России** — зарубежные хостинги из России открываются с перебоями.

## 1. Что арендовать

- Ubuntu 24.04 (или 22.04, Debian 12), процессор x86_64.
- 1 ядро, 1–2 ГБ памяти, от 15 ГБ диска. Этого хватит на старт.
- Доступ root по SSH (пароль или ключ провайдер присылает после оплаты).

## 2. Адрес (домен)

- **Свой домен** (например, `twm-market.ru`): в настройках DNS создайте запись
  `A` для нужного имени (например, `api.twm-market.ru`) с IP сервера.
- **Без домена**: установщик предложит бесплатный адрес вида
  `203-0-113-5.sslip.io` — он сам указывает на IP сервера.

## 3. Установка

На Windows откройте PowerShell и подключитесь к серверу:

```powershell
ssh root@IP_СЕРВЕРА
```

На сервере:

```bash
curl -fsSL https://github.com/TWMandem/TWM-Market/releases/download/server-latest/install.sh -o install.sh
sudo bash install.sh
```

Если сервер не может скачать файлы с GitHub, скачайте на компьютере три файла
из релиза [server-latest](https://github.com/TWMandem/TWM-Market/releases/tag/server-latest)
(`install.sh`, `twm-server-linux-x64.tar.gz` и `.sha256`), загрузите их на сервер
и запустите установщик из той же папки:

```powershell
scp install.sh twm-server-linux-x64.tar.gz twm-server-linux-x64.tar.gz.sha256 root@IP_СЕРВЕРА:/root/
```

Установщик спросит домен и email для Let's Encrypt (можно оставить пустым),
поставит PostgreSQL и nginx, получит HTTPS-сертификат и запустит сервер.
В конце он покажет адрес — проверьте его в браузере: `https://ВАШ_АДРЕС/health`.

## 4. Администратор

```bash
sudo twm admin-create --login ВАШ_ЛОГИН --email ВАШ@EMAIL
```

Пароль спросит с клавиатуры (ввод не отображается). При первом входе в
админ-панель приложение попросит включить двухфакторный вход.

## 5. Свой домен

1. Купите домен у любого регистратора (например, `twm-market.ru`).
2. В DNS домена добавьте запись **A**: имя `api`, значение — IP сервера.
3. Когда домен заработает (от часа до суток), выполните на сервере:
   ```bash
   sudo twm set-domain api.twm-market.ru
   ```
   Команда проверит, что домен указывает на этот сервер, выпустит сертификат
   и переведёт сервер на новый адрес. Старый адрес тоже продолжит работать,
   поэтому уже установленные приложения не отключатся.

## 6. Почта через Yandex Cloud Postbox

Postbox отправляет письма по HTTPS, поэтому ему не мешает то, что многие
VPS закрывают почтовые порты. Первые 2000 писем в месяц бесплатны.
Нужен свой домен (см. выше).

1. Зайдите в [консоль Yandex Cloud](https://console.yandex.cloud), создайте
   платёжный аккаунт.
2. **Сервисные аккаунты** → создайте аккаунт `twm-mail` с ролью `postbox.sender`.
3. Откройте его → **Создать новый ключ → Статический ключ доступа**.
   Сохраните идентификатор и секретный ключ — секрет показывается один раз.
4. **Cloud Postbox → Создать адрес**: домен `twm-market.ru`, DKIM — автоматически.
   Консоль покажет DNS-записи — добавьте их в DNS домена у регистратора.
   Там же стоит добавить:
   - TXT для `@`: `v=spf1 include:spf.postbox.yandexcloud.net ~all`
   - TXT для `_dmarc`: `v=DMARC1;p=none`
5. Дождитесь, пока Postbox подтвердит домен.
6. На сервере `sudo nano /etc/twm/twm.env`, вместо `MAIL_TRANSPORT=console`:
   ```
   MAIL_TRANSPORT=postbox
   POSTBOX_KEY_ID=идентификатор_ключа
   POSTBOX_SECRET="секретный_ключ"
   MAIL_FROM="TWM Market <noreply@twm-market.ru>"
   ```
7. `sudo twm restart`, затем проверка: `sudo twm mail-test ВАШ@EMAIL`.

### Почта через SMTP (если хостинг не закрывает порт 465)

Пока почта не настроена, коды пишутся в журнал: `sudo twm logs`.
Для отправки через Яндекс:

1. Заведите ящик для площадки, например `twm.market@yandex.ru`.
2. В настройках аккаунта Яндекса создайте **пароль приложения** для почты.
3. Откройте настройки сервера: `sudo nano /etc/twm/twm.env` и замените
   `MAIL_TRANSPORT=console` на блок из подсказки в этом файле.
4. `sudo twm restart` и проверьте в журнале строку «Почта: подключение … в порядке».

## Команды

| Команда | Что делает |
|---|---|
| `sudo twm status` | состояние и версия |
| `sudo twm logs` | журнал сервера (выход — Ctrl+C) |
| `sudo twm update` | резервная копия, затем свежая сборка с GitHub |
| `sudo twm rollback` | вернуть предыдущую сборку |
| `sudo twm backup` | копия базы и скриншотов в `/var/backups/twm` |
| `sudo twm restart` | перезапуск после правки `/etc/twm/twm.env` |
| `sudo twm reset-2fa --login ЛОГИН` | сбросить двухфакторный вход администратора |
| `sudo twm mail-test ВАШ@EMAIL` | отправить тестовое письмо |
| `sudo twm set-domain api.example.ru` | перейти на свой домен |
| `sudo twm setup-offsite` | настроить копии вне сервера (Object Storage) |
| `sudo twm offsite-list` | список копий в хранилище |
| `sudo twm backup-passphrase` | пароль шифрования копий — сохраните его вне сервера |
| `sudo twm set-site twm-market.ru` | сайт площадки на основном домене (раздел 8) |
| `sudo twm delete-user --login ЛОГИН` | удалить аккаунт по просьбе игрока (раздел 9) |

Резервная копия делается каждый день в 04:30 и хранится 14 дней на самом
сервере. Время от времени скачивайте копии к себе:

```powershell
scp -r root@IP_СЕРВЕРА:/var/backups/twm .\twm-backups
```

## 7. Копии вне сервера (Yandex Object Storage)

Если VPS сломается или его удалят, копии на нём пропадут вместе с ним.
Поэтому каждую ночь `twm backup` может ещё и шифровать копию и загружать
её в Object Storage Yandex Cloud (тот же аккаунт, что для почты Postbox).
Копии хранятся 30 дней, более старые удаляются сами.

1. Консоль Yandex Cloud → **Object Storage** → «Создать бакет»: любое имя
   (например, `twm-backups-ВАШЕ_ИМЯ`), доступ на чтение и к списку — **ограниченный**,
   класс хранилища — холодное или стандартное.
2. **Identity and Access Management** → «Сервисные аккаунты» → создать аккаунт
   `twm-backup` с ролью **`storage.editor`** (на каталог).
3. В сервисном аккаунте → «Создать новый ключ» → **«Создать статический ключ доступа»**.
   Покажутся идентификатор и секретный ключ — секрет виден один раз.
4. На сервере:
   ```bash
   sudo twm setup-offsite
   ```
   Команда спросит имя бакета, идентификатор и секретный ключ (секрет при вводе
   не отображается), создаст пароль шифрования и проверит доступ.
5. **Сохраните пароль шифрования вне сервера** (менеджер паролей):
   `sudo twm backup-passphrase`. Без него копию не расшифровать.
6. Проверка: `sudo twm backup`, затем `sudo twm offsite-list`.

Если ночная загрузка не удалась, ошибка появится в админке в разделе «Ошибки».

### Восстановление из копии

Скачайте из бакета файлы нужного дня (`db-….dump.enc`, `uploads-….tar.gz.enc`)
и на сервере выполните:

```bash
openssl enc -d -aes-256-cbc -pbkdf2 -iter 200000 -in db-ДАТА.dump.enc -out db.dump   # спросит пароль шифрования
openssl enc -d -aes-256-cbc -pbkdf2 -iter 200000 -in uploads-ДАТА.tar.gz.enc -out uploads.tar.gz
sudo systemctl stop twm-api
sudo -u postgres pg_restore --clean --if-exists -d twm db.dump
sudo tar -xzf uploads.tar.gz -C /var/lib/twm && sudo chown -R twm:twm /var/lib/twm/uploads
sudo systemctl start twm-api
```

На новом сервере сначала выполните установку (раздел 3), затем эти команды.

## 8. Сайт twm-market.ru

Сайт (страница приложения, правила, конфиденциальность, безопасная сделка) входит в
сборку сервера и обновляется вместе с ней (`sudo twm update`). Включается один раз:

1. В DNS у регистратора домена создайте две записи `A` с IP сервера:
   `twm-market.ru` (часто обозначается `@`) и `www.twm-market.ru` (`www`).
   Запись `api` не трогайте.
2. Подождите, пока записи начнут работать (обычно от 15 минут до нескольких часов).
3. На сервере: `sudo twm update`, затем `sudo twm set-site twm-market.ru`.
   Команда проверит DNS, настроит nginx и получит сертификат HTTPS.

Если `www` не настроен, сайт заработает только на `twm-market.ru` — команду можно
повторить позже. Её же стоит повторить, если в описании выпуска сказано, что
изменились настройки сайта (`deploy/nginx-site.conf`).

Главная страница показывает число объявлений, продавцов и сделок, когда объявлений
станет 30 и больше. Цифры берутся с сервера (`/v1/public/stats`), без личных данных.

## 9. Удаление аккаунта по просьбе игрока

Игрок пишет на support@twm-market.ru с адреса, указанного в аккаунте. Проверьте,
что письмо пришло именно с этого адреса, затем:

```bash
sudo twm delete-user --login ЛОГИН
```

Команда покажет, что будет удалено, и попросит ввести логин ещё раз. Удаляются профиль,
игровые профили, объявления с фото, избранное, подписки, уведомления и сеансы.
Переписка, сделки и отзывы остаются у собеседников, но без логина и email: аккаунт
обезличивается и блокируется. Сотрудника площадки так не удалить — сначала снимите роль.
Ответить игроку нужно в течение 30 дней (так написано на странице «Конфиденциальность»).

## Где что лежит

- `/etc/twm/twm.env` — настройки и секреты (не публикуйте этот файл);
- `/opt/twm/current` — текущая сборка (Node.js внутри, отдельно ставить не нужно);
- `/var/lib/twm/uploads` — скриншоты и иконки;
- `/var/lib/twm/uploads-private` — скриншоты для подтверждения ников (только для модераторов, удаляются после проверки);
- база PostgreSQL `twm` доступна только с самого сервера.
